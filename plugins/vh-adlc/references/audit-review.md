# Independent audit batch review

Use the common `review-protocol.md` model/independence/isolation rules. This audit-specific review
adds obligations to ordinary maintenance; do not dispatch an unchanged dependency reviewer and
claim it covered them. Required inputs: source repository, exact final commit, audit record path,
original selected IDs/workstream and any included carried report scope, current delivery limitations,
engineering-docs revision and this procedure. Read applicable pinned pages and local project policy.
Missing inputs or an unavailable independent route leave `review pending` with a complete handoff.

Read only. Leave source, index and every ref unchanged; put scratch outside the repository. Read the
committed Definition, every original finding and actual source evidence. Review the full publication diff
from the fetched default-ancestor Scope baseline, including any carried ledger commit. The helper observes the actual remote default read-only and requires its tip to match both that baseline and the existing tracking ref; an author-selected branch or stale/offline observation cannot substitute for it. It never fetches or moves a ref during review. Task base is
the post-ledger point for attributing repair/red evidence, not a way to hide earlier published changes.

Verify each member's cited pre-existing contract and restoration eligibility. New semantics, an
intentional boundary/format/migration/delivery change or unresolved product judgment needs the
feature/owner route. Verify complete selection, coupled bundles and every disposition. For authored
repairs inspect real pre-fix regression failure, repair commit and actual final-head required checks.
For assessment-only members require honest current scenario/challenge/check evidence and no fake
red. UNKNOWN/PARTIAL or missing required evidence blocks the requested whole batch. An all-assessment
selection creates no empty repair PR.

Challenge every proposed FIXED/MOOT against its original failure or applicability. Absence of an old
line or a renamed symbol is not MOOT. Inspect siblings and other surfaces. Record the challenge for
each member explicitly if this review also supplies its independent adversarial check. An author's
proof string, artifact digest or keyword list cannot establish semantic truth. Execute required safe
checks independently where possible; missing execution evidence stays a finding. No live/remote action
is authorized merely by reviewing. Inspect cleanup intents, required live gates and permitted residuals;
permission denial/token shortage/skipping is not the documented unreachable-path exception.

Check all carried IDs, original source/date/snapshot/evidence/challenges and exact owner inclusion.
Reject omitted scope, missing member challenge, checks only for a sibling, or review of only
Task-base-to-head. Preserve ledger IDs, anchors, finding content, table shape and historical notes.

Verify `source_target` is a real post-repair commit and the ledger's Verified source. Compare its Git
objects to the final review commit: only the Definition-declared ledger and record paths may differ; generated indexes must already
be frozen with source, and ledger-content-derived external indexes are unsupported in this profile;
source, tests, config and verification inputs must match. Final checks still target the actual final
head. A placeholder, pre-fix target, changed input or post-review ledger edit is a finding. A provisional
local candidate is reviewable but not a published completion verdict before this review and all gates.

Use `scripts/audit/cli.ts batch-check --repo <source> --input <private-bundle.json>` for structural
bindings, then inspect semantics and actual transcripts yourself. These records are operator attestations,
not OS-enforced proof. Confirm unrelated work/index/refs and pending evidence survive recovery/cleanup.

Start with `MODEL: <actual id>` (or unknown only when no identity is supplied). Return complete shared
FINDING records or exactly NO FINDINGS, without a footer. The caller stores them verbatim with exact
target/model/isolation. Source, ledger, verification inputs or Definition changes require renewed
review; true append-only record evidence/review/state bookkeeping may retain freshness. Separate
current delivery authority and the consumer's exact current-head/CI/merge conditions remain required.
