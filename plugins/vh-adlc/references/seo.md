# Free-first website SEO assessment

Assess whether the requested website is discoverable, useful for its search
audience and measurable. Separate technical search readiness, observed search
performance, content opportunities and conversion clarity. These do not by
themselves prove business viability or future traffic.

## Scope and available evidence

Read the adopter's instructions and SEO adapter. Establish the canonical host,
owned aliases, audience, target countries/languages, relevant pages, existing
research and output locations. Infer these from available context before asking.
An old host and a future official host need separate observations. Do not mix a
consultancy site with its product site or other clients in an agency account.

Inventory the accessible sources first. For each, record available, partial,
unavailable, expired or historical, with its date range and scope. A free plan
may require ownership verification. Check current official tool limits when they
affect the procedure; never assume free includes API access, exports, JavaScript
rendering or historical data. Use authorized connections or supplied exports.
Do not open somebody's existing authenticated browser session or create accounts.
If setup is missing, explain the smallest setup needed while continuing public
checks. Never paste credentials into prompts, URLs, HTML, reports or exports.

## Free sources and their jobs

- Google Search Console: first-party Google queries, pages, countries, devices,
  clicks, impressions, CTR, position and indexing evidence. Use an authorized
  read-only connection/API or supplied CSV/JSON. Record property and date range;
  respect privacy filtering and partial/top-row API results. An API call's POST
  method does not make the read-only search-analytics query a publishing action.
- Bing Webmaster Tools: first-party Bing performance, indexing and technical
  findings from an authorized read-only connection or supplied export. Keep its
  engine and metrics separate from Google's. Registration is not historical
  measurement, and a recent setup may have no observations yet.
- Ahrefs Free: verified-site backlink, organic-keyword and audit evidence within
  the current free allowance. Do not assume its paid API/MCP or CSV export is
  free. If exports are unavailable, retain a permitted dated summary with source
  provenance and mark it partial; do not bypass plan restrictions or promise a
  full raw export. Metrics are provider estimates, not first-party visit counts.
- Public HTTP/browser checks: always useful without an SEO subscription. Inspect
  status codes and redirects, robots.txt, sitemap XML, canonicals, robots meta
  and headers, initial HTML versus rendered content, titles/descriptions/headings,
  links, image descriptions and the actual crawl path to key public pages.
  Bound the crawl to the authorized hosts/pages; respect robots directives and
  host load. Use safe read requests without browser credentials, stop at access
  controls, and do not fetch signed-in routes or unrelated tenants. Preserve
  redirect hops before following them. A 200 response alone proves little.
- Screaming Frog Free or equivalent local tools: bounded technical crawling.
  Respect the current URL and rendering limits. For a JavaScript site whose free
  crawler cannot render it, compare raw HTML with a fresh browser context instead
  of buying a licence or declaring the rendered content absent.
- PageSpeed Insights or local Lighthouse: page-level lab diagnostics and any
  available field/Core Web Vitals data. Label lab versus field, page versus origin
  and mobile versus desktop. Missing field data is not a zero performance score.

A search-engine `site:` query can be a discovery hint; it is not a complete index
count or a substitute for the owner's search-performance records. No source is
required to have data for a new or small site. Avoid collecting every tool's
version of the same measurement when it adds no useful evidence.

## Optional Semrush

Use it only through an authorized local credential/client or a connected tool.
Keep the secret local and out of client bundles and archives. Start with relevant
existing exports. If access works and fresh data would change the assessment,
use bounded reports with the correct target type, country database, date and
row limit. Observe reported usage and preserve the request parameters and result
before making the next request. Do not buy units or a plan, create campaigns or
probe unrelated projects. Verify response bodies; an HTTP 200 or client exit 0
alone does not establish a successful report.

A `no_data` result means no data for that exact request. Record it without
turning it into zero traffic, no indexing or universal absence across reports.
Do not repeat identical terminal requests or fan out parameter variations merely
to force a value. Use other accessible first-party/public sources for their own
measurements, preserving the distinction. Authentication, expiry, quota and
provider failures remain different outcomes. Stop optional calls when access
fails; complete the assessment from free sources and dated saved evidence.
Old exports remain useful historical evidence after the key expires, not fresh
measurements. Never infer a current ranking from an old response.

## Evaluate and prioritize

Follow the main public journeys, including the homepage, primary product/task
pages, articles and contact/signup/install path. Check whether a crawler receives
meaningful content and whether a visitor can understand the offering and take
its intended next step. Keep canonical-host migration and deployment findings
separate from repository source: merged, built, deployed, crawlable and indexed
are distinct states. A draft visible in a private preview is not a live page.
Report noindex as an observed policy, considering the owner's launch intent.

Review search intent, useful original answers, internal linking, topic overlap,
headings and metadata. Inspect the actual images against their passage; an image
or code block count is not content quality. Do not infer performance from AI
writing style or invent volume, difficulty, conversions, competitor results or
an exclusive market position. Use the adopter's article workflow for later edits.

Keep country, language, engine, device and time windows explicit. Compare like
periods and properties. A country is not a language and a continent is not one
regional database. Match paid keyword estimates to their provider/methodology;
first-party clicks and estimated third-party traffic remain separate. A small
sample or absent baseline warrants a limited conclusion.

Prioritize crawl/indexing blockers and measurement gaps, then useful content and
user-path improvements supported by the evidence. Each finding names the affected
URL(s), observation, impact, proposed action, confidence and a concrete validation
step. Separate observed defects from hypotheses and optional opportunities.
Describe viability as ready, needs work or insufficient evidence per dimension,
with reasons; avoid an invented aggregate score or traffic forecast. Do not
perform the fixes during an assessment unless the owner separately requested them.

## Evidence that outlives access

Use the adopter's established report and ignored/private export locations. Save
permitted raw responses/exports and a machine-readable findings table (CSV or
JSON), with source, target/property, country, period, retrieved time, status and
coverage. Preserve request parameters without authentication headers or tokens.
Record observed unit usage as reported, not an invented account debit total.

Write a manifest with file SHA-256 digests and enough scope/method metadata to
repeat the assessment. Verify the files and hashes before reporting completion.
Keep missing numeric values blank/null with an explicit outcome, never zero by
default. Preserve ownership of third-party reports and applicable export limits.
Exclude credentials, cookies, unrelated projects and private query/user details
not needed for this task. Redact any discovered secret before saving it; note
that the preserved evidence was redacted. A safe summary may be all a source
permits. An export directory is not permission to commit or publicly host data.

Return the prioritized findings, per-source coverage, what remains unknown, report
and export paths, and exact checks performed. State separately what needs owner
verification or account setup and what can be assessed now. No account creation,
subscription, public message, issue update, scheduled monitoring, commit, push,
publication or deployment is implied by an SEO assessment.

## Primary references

Recheck terms when using these services; this procedure does not freeze free-plan
limits or guarantee data availability.

- [Google Search Console](https://support.google.com/webmasters/answer/9128668): verification and first-party search tooling.
- [Search Analytics query](https://developers.google.com/webmaster-tools/v1/searchanalytics/query): dimensions, read authorization and row limits.
- [Bing Webmaster Tools](https://www.bing.com/webmasters/about): free verified-site tooling.
- [Bing Search performance](https://www.bing.com/webmasters/help/search-performance-c680da36): engine-specific metrics and exports.
- [Ahrefs free access](https://help.ahrefs.com/en/articles/13002606-what-can-i-use-for-free-in-ahrefs): verified-site reports and allowances.
- [Ahrefs plan comparison](https://help.ahrefs.com/en/articles/6117209-what-s-the-difference-between-all-ahrefs-subscription-plans): API and export restrictions differ by plan.
- [Screaming Frog Free](https://www.screamingfrog.co.uk/seo-spider/user-guide/general/): crawl and rendering limits.
- [PageSpeed Insights](https://developers.google.com/speed/docs/insights/v5/about): lab and field data scope.
