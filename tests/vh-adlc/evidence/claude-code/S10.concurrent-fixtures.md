## Deterministic proof

The [fixture test](../../fixtures.test.ts) builds two accepted, claimed features with separate source,
test and document paths. The primary feature owns the greeting worktree; the farewell feature owns the
existing other worktree.

The test observed:

- The real binary's in-progress gate passed for both documents in their owning worktrees.
- Both feature test scripts initially failed.
- A farewell implementation commit changed only its worktree; its test passed while greeting still
  failed.
- A greeting implementation commit then changed only its worktree; both feature tests passed.
- The greeting test in the farewell worktree still failed, showing that the greeting commit had not
  leaked across worktrees.
- Neither the local nor remote default-branch ref changed during those implementation steps.
- Unrelated work and the worktree paths and branches were unchanged.

The new test initially failed because the second-feature fixture did not exist. After implementation,
`bun test tests/vh-adlc/fixtures.test.ts --test-name-pattern 'both feature worktrees'` passed.
The complete `bun test tests/vh-adlc` run then returned 67 passes, zero failures and 244 assertions.

## Scenario change

[S10.1](../../scenarios/run.ts) now gives the other worktree its own planned and claimed farewell
feature. While greeting waits for the owner's handoff, a separate session receives the farewell
handoff and implements its first task. Greeting then resumes in its original session.

The checks require implementation commits and passing tests for both features, checked task records,
preservation of the paused worktree in each direction, no cross-feature file changes, no feature push,
no default-branch change and no worktree creation or removal. The sessions are interleaved, not
simultaneous processes.
