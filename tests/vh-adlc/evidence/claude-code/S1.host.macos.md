## Fixture regression

On `17d3e6a`, `bun test tests/vh-adlc` returned 55 passes and two failures:

- The fixture installer rejected the cached binary because its digest differed from the wrapper's lock.
- Teardown tried to read `f.dir` after fixture construction had thrown.

The [fixture builder](../../fixtures/build.ts) separated the real binary's cache with XDG_CACHE_HOME.
The macOS installer uses HOME/Library/Caches instead, so the real binary and wrapper occupied the
same cache entry. The real-binary installer now receives its own HOME as well as its existing Linux
cache override. Production checksum verification and lock files are unchanged.

The [fixture tests](../../fixtures.test.ts) retain their scratch path independently of construction.
A failed setup then reported only its original error, and its scratch directory was removed.
The new cache-separation test verifies the real binary and both fixture plugins in the same home.

After the fix, `bun test tests/vh-adlc` returned 66 passes, zero failures and 225 assertions on this Mac.
The existing installer tests still rejected incorrect asset and binary digests and tampered caches.
The [CI workflow](../../../../.github/workflows/ci.yml) runs the same suite on macOS in addition to its
existing Linux job. The existing check names remain unchanged.
