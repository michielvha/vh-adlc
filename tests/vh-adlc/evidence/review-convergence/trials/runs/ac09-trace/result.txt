FINDING: F-02
KIND: judgement
SEVERITY: should-fix
WHERE: Design (line 30), Acceptance Criteria (AC-01, line 34)
EVIDENCE: Design says probe.sh "exits 2 when the check times out" but does not define the exit status for other failures. probe.sh:2 runs `curl -fsS http://localhost/health >/dev/null` as its last command, so today the script exits with curl's own status: 7 for connection refused, 22 for an HTTP error under -f, 28 for a timeout. curl itself uses exit 2 for "failed to initialize", so passing curl's status through for non-timeout failures would make exit 2 ambiguous. One implementer would map only curl 28 to 2 and pass the rest through; another would map every failure to 2. Callers that read the current exit codes are affected by the change, and the document does not mention them.
PROPOSAL: State the exit status for success, timeout and every other curl failure, and keep timeout distinct from curl's own exit 2. Add a criterion and Test Plan row for the non-timeout failure path.
