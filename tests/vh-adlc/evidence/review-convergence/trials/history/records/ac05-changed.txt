FINDING: F-04
KIND: judgement
SEVERITY: should-fix
WHERE: Test Plan, AC-01 row (docs/specs/feature.md:40); Design (docs/specs/feature.md:30)
EVIDENCE: The proof reads "lint-msg.sh matches the subject against `^[a-z]+: [a-z].*$`". That describes the script's internals. It does not say how to run the script or what counts as a pass. Neither the proof nor Design says how lint-msg.sh gets the subject (an argument, stdin, or a commit message file as a commit-msg hook) or what accept and reject mean (for example exit 0 and non-zero). A script that contains this regex but still exits 0 for every input could be read as passing on inspection. Two implementers could also build different interfaces.
PROPOSAL: Define the interface and exit status in Design. Rewrite the proof as a test that runs lint-msg.sh on each must-pass and must-fail subject and checks the exit status.
